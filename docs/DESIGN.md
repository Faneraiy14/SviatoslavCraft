## ВИРІШЕНО

### Концепція
Voxelin — власна воксельна гра на Java + LWJGL, задумана як «Майнкрафт без його дірок». Частина оригіналу лишається впізнаваною, але майже все переписується: крафти, механіки, сюжет.
Довгостроковий проєкт, терміни не є пріоритетом. Код пише Святослав (з Claude), ідеї обговорюються разом із Нікітою.

Три проблеми Майнкрафта, які Voxelin вирішує:
1. **Оптимізація** — закладена в архітектуру з самого початку, а не латками потім.
2. **API для модів** — вбудоване в ядро гри, без «прошарків» між грою і кодом модів. *05.11.2026, рішення Святослава:* це власне API Voxelin, а не FL Loader (20.10.2026 його зробили окремим, хоча тут було записано «FL Loader», - відхилення помітили лише 05.11). Від FL Loader не беремо: латання байткоду Voxelin не потрібне, а головне - щоб нові частини API додавались без переписування ядра (правила - `docs/MODDING.md` «Як росте API», стереже `VoxelinApiTest`). Завантажувач завжди в грі: є моди - вантажить, нема - пропускає. *05.11.2026, ідея Святослава «як Paper, але щоб гравцям не качати моди»:* окремого API плагінів НЕ робимо (це був би той самий поділ «ваніль/лоадер», і кожну можливість довелось би додавати двічі) - натомість **моди на сервері = плагіни**: хост завжди (без прапорця) надсилає гостю вміст своїх модів даними (протокол 5, `S_CONTENT`; гість будує окремі реєстри гри `Game.forHost`), команди модів з правами 0 виконуються для гостей на сервері, сервіс `Players` дає модам діяти на конкретного гравця. Позначка «мод лише для клієнта» з'явиться разом з API клієнта (інтерфейс, рендер) - зараз такого API нема.
3. **Гра «кидає» після дракона** — дракон є серединою гри, а не фіналом.

### Технічні принципи
- **Мова рушія — Java (21) + LWJGL.** Не NyxilumLang і не своя JVM: VM NyxilumLang ~100× повільніша на щільних циклах і не має OpenGL; самописна JVM була б повільнішою за HotSpot. (15.10 і 20.10.2026)
- **Блоки як дані, а не код.** Єдиний реєстр, де блок описаний властивостями: текстура, твердість, світло тощо. Однаково для блоків гри, гравців і модів. Ванільний вміст реєструється через той самий API, що й моди.
- **Ядро окремо від рендера й вводу.** Світ, блоки, моби й скрипти живуть у ядрі, яке нічого не знає про вікно й клавіатуру. Тоді мультиплеєр пізніше — добудова, а не переписування.
- **Тонкий шар API між скриптами/модами й ядром.** Один інтерфейс для всіх рівнів створення контенту. API має власну версію, тож моди не ламаються з кожним оновленням гри.
- **Скрипти гравців — на NyxilumLang (20.10.2026), але ВІДКЛАДЕНО.** Рівні 2–3 (блоки як у Scratch і повний код) пишуться мовою Святослава. Зараз їх не робимо, але архітектура готується так, щоб вбудувати було нескладно:
  - усі зміни світу йдуть через один API ядра (команди, моди й майбутні скрипти користуються тим самим);
  - події й команди описані як дані, а не жорстко в коді;
  - ядро вміє виконувати дії від імені «джерела» з правами й лімітами (гравець, мод, скрипт).

  Запуск `nx` окремим процесом із пісочницею зроблено 04.11.2026 (див. «Наступні кроки», п. 7 і MODDING.md).
- **IDE в грі - ні, повної не буде (29.10.2026, погодив Святослав).** У грі - блоки як у Scratch і невелике вікно коду з консоллю (рівні 2-3). Серйозні моди пишуться в зовнішньому редакторі (NyxilumIDE), а гра підхоплює зміни без перезапуску (hot reload).
- **Пісочниця для скриптів:** без доступу до файлів і мережі без дозволу, з лімітом часу й пам'яті.
- **Швидкодія з першого дня:**
  - блоки — номери в масивах, а не об'єкт на кожен блок;
  - склеювання граней, буфери на GPU, один виклик малювання на чанк;
  - текстурний атлас;
  - відсікання невидимого (поле зору, печери);
  - генерація й мешинг у фонових потоках;
  - спрощені далекі чанки;
  - файли-регіони зі стисненням і номером версії формату;
  - вбудований тест FPS і часу кадру.
- **Зараження — клітинний автомат лише біля гравця.** Далекі чанки «доганяють» розрахунком при заході.
- **Dev-запуски (бенчмарк, знімки) не захоплюють курсор і не відбирають фокус** - вони йдуть на реальному столі користувача.
- **Одиночна гра — основа; мережа — для будівництва разом.** Хост відкриває свій світ для локальної мережі, гості будують у творчому режимі (див. п. 8). Світи зі скриптами передаються файлом `.vxworld`.
- **Структури** не беруться з коду чи файлів оригіналу, а будуються вручну. Прототипи можна будувати на окремому тестовому сервері Minecraft через RCON і потім конвертувати у формат Voxelin. Живий сервер Святослава для цього не використовується.
- **Назва скрізь — Voxelin.** Пакет `com.sviatoslav.craft`, клас `SviatoslavCraft` і заголовки — перейменувати на першому етапі.

### Свій світ і контент гравця
Гравець може вигадувати власні блоки, малювати їх і редагувати шаблони світів. Три сходинки, щоб код не був бар'єром:
1. Команди (`/fill`, `/setblock`) — для всіх, без програмування.
2. Блоки в стилі Scratch (як у NyxilumIDE). Кожна блокова програма стає справжнім кодом, і гравець бачить, у що вона перетворюється.
3. Повний код для просунутих, з консоллю в грі (на кшталт Code Builder з Education Edition).

Усі три рівні працюють поверх одного API. Додатково: шаблони світів, які можна редагувати, і візуальний редактор блоків.

### Звичайний світ після проходження
«Гра кинула» — це не брак контенту, а брак напрямку. Що має триматися у звичайному світі:
- **Світ пам'ятає гравця:** поселення ростуть від його допомоги, з'являються дороги й місця, названі на його честь.
- **Живі події:** зараження, міграції мобів, сезонні зміни біомів.
- **Інструменти для власних цілей:** карти, мітки, проєкти з прогресом (збудуй місто, зроби колекцію).
- **Довгі досягнення без кінця, але з сенсом** — не «убий 1000 зомбі».
- **Нові виміри:** окрім Незера й Енду — ще один або кілька нових світів; зміни в самому Незері. На Sift (чутки з Minecraft Live) не закладаємось.

### Вхід в Енд — лише в алмазній броні (20.10.2026)
- Портал в Енд **запалюється лише тоді**, коли гравець, який ставить **останнє** око, має на собі **повний надітий комплект**: шолом, нагрудник, поножі й черевики.
- Кожна частина має бути **алмазною або незеритовою** (незерит — покращений алмаз і теж рахується).
- Броня в інвентарі чи скрині не рахується — лише надіта.
- Інструменти й зброя **не вимагаються**.
- Якщо умова не виконана, портал не запалюється, а **останнє око повертається в інвентар гравця** і не губиться. Гравець має отримати зрозуміле пояснення, чому так (запис або повідомлення).
- Мета: зробити Енд складнішим і дати сенс добувати алмазну броню.
- Саме око Енду (рецепт, вигляд, поведінка) теж буде перероблено — див. «На обговорення».

### Яйце дракона: розвилка
Після вбивства дракона з'являється яйце і НПС. Через кнопку відкривається HUD записів, де НПС «подумки» пояснює, що відбувається. Гравець обирає одну з двох гілок, і обидві мають бути валідними. **Гравець знає наслідки до вибору.**

| Гілка | Що робить гравець | Що змінюється |
|---|---|---|
| 1. Ритуал | Залишає яйце, готується, проводить ритуал | Енд змінюється, починається друга стадія з двома новими босами |
| 2. Зараження | Забирає яйце, запускається таймер 30 ігрових днів | Зараження звичайного світу, яке можна зупинити |

Ритуал не повинен бути очевидно кращим за зараження.

### Гілка 2: зараження
- **Ядро:** гравець ставить яйце (ідея Нікіти), і воно стає ядром зараження. Поки зараження активне, ядро не можна зламати, перенести чи обійти. Місце — це вибір гравця.
- **Таймер:** 30 ігрових днів. Якщо носити яйце з собою, воно саме пускає корені там, де стоїть гравець. Про остаточність попереджає підказка або запис **до** постановки.
- **Поширення:**
  - жилами по блоках до вузлів;
  - у темряві швидко, біля світла, води й споруд гравця — повільно;
  - вузли можна знайти й зруйнувати.
- **Що змінює:**
  - блоки мутують за біомом: ліс скам'яніває, пустеля спікається в скло, болото «дихає»;
    - *Зроблено 29.10.2026:* навколо нового наросту колонки мутують: колоди → скам'яніла колода (і крона навколо обсипається), пісок → спечений пісок, пісковик → скло дюн, мул і трава в болоті → дихальний мул (поруч із ним вода вже не стримує ріст), решта трави блідне, як у Тихих пустищах. Мутації в `blight.dat` з оригіналом: після лікування світ заживає поступово за ~2 доби (зламане гравцем не відновлюється), після спалення й приручення - назавжди.
  - тварини тікають, вороги в заражених зонах сильніші;
    - *Зроблено 29.10.2026:* з активної пори (у тиху - лише сліди) тварини в зоні час від часу тікають від ядра, вороги б'ють ×1.5.
  - поселення можна евакуювати, захистити або втратити.
- **Фази:**
  - Тиха (дні 1–10) — дрібні сліди, які можна сплутати зі слідами Херобрина;
  - Активна (дні 11–20) — жили й вузли;
  - Криза (дні 21–30) — зараження наступає на поселення.
- **Як зупинити:**
  - **вилікувати** — потрібен інгредієнт із міжсвіття;
  - **приручити** — зараження стає ресурсом, але з ціною;
  - **спалити** — швидко, але лишається кратер назавжди.

  Зупинка має бути досяжною, але не тривіальною.
- *Попередження зроблено 29.10.2026:* небо сіріє й темніє з порою (активна 15%, криза 35%, прорив 50%), петлі оточення стихають (тиха ×0.7 → прорив ×0.1), записи «Жили» (10-й день), «Криза» (20-й), «Прорив» (30-й).
- **Якщо гравець нічого не робить:** чітке попередження (небо темніє, зникають звуки, запис у HUD), потім останній шанс — складніший і дорожчий, кульмінація. Руйнування йде поступово, по зонах.

### Провал
- Провал змінює світ, але не стирає його, і втрата одразу стає квестом.
- Закриті виміри пов'язані: Незер повертається через Енд, Енд — через міжсвіття.
- Не можна прибирати ресурси без заміни: гравець не повинен застрягти.
- Попередження мають бути раніше й гучніші за саму втрату.

### Міфи
- **Сутність на кшталт Херобрина:**
  - ніколи не підтверджується, не є мобом, не атакує першою, не має хітбокса;
  - з'являється рідко й не за розкладом, лишає сліди;
  - не має ачівки чи запису в журналі;
  - його «допомога» — справжня механіка, але завжди трохи не та: ніколи двічі однаково, подякувати не можна, і поруч у момент допомоги його не буває.
  - частина HUD-записів може бути від нього: обірвані, перекреслені.
- **Міжсвіття** — простір між вимірами, про який гра не розповідає:
  - зв'язка між 4–6 вимірами;
  - дешеве в контенті, дороге в емоції;
  - вузол усіх катаклізмів, змінюється зі станом світу;
  - місце Херобрина;
  - ключ до лікування й відновлення.

### Принципи дизайну
- Гравець знає наслідки до вибору.
- Кожна загроза дає дії, а не лише тривогу.
- Механіка, а не атмосфера.
- Обидві гілки валідні.
- Провал змінює світ, але не стирає.
- Міфи не підтверджуються.
- Глибина важливіша за кількість: краще 3 глибокі виміри, ніж 7 поверхневих.
- Спершу вертикальний зріз: один світ, ядро з модами, яйце з двома гілками, міжсвіття.
- Фіксувати рішення й причини — у цьому файлі.

## НА ОБГОВОРЕННЯ (пропозиції Claude, 20.10.2026 — ще не затверджено)

### Одна історія замість трьох
Дракон — **замок на Шві** між вимірами, яйце — насіння міжсвіття, а НПС із записами — **Сторож Шва**, родом з міжсвіття. Тоді:
- **Ритуал** — запечатати Шов заново, тому Енд і змінюється.
- **Зараження** — Шов прорвався у звичайний світ, і жили — це сам міжсвіт, що проростає.
- **Херобрин** живе в міжсвітті, але це ніколи не підтверджується. Є лише непрямі докази: його сліди частіше там, де Шов тонкий.

### Ритуал і два боси
- **Ткач і Розплітач** — дві сили, які тримав дракон:
  - Ткач будує стіни, острови й клітки з блоків Енду;
  - Розплітач розбирає землю під ногами, і його суть — та сама сила, що в гілці зараження стає жилами.
- **Бій з обома одночасно:** коли вбиваєш одного, другий лютує, тож їх треба тримати в балансі.
- **Чому не одразу:** потрібні три **якорі** — зі звичайного світу, Незеру й Енду. Тоді є причина повернутись у змінений Незер. Яйце ще кілька ночей «визріває» біля якоря.
- **Баланс гілок:** ритуал безпечний для світу, але має найважчі бої; зараження ризикує світом, зате дає найбільше нових матеріалів і механік.

### Відповіді на відкриті питання
1. **Головна розв'язка зараження.** Жодна — три різні пост-гри:
   - вилікувати — найдовше, зате постійний доступ до міжсвіття;
   - приручити — ядро треба «годувати», інакше воно спалахує; технологічний шлях;
   - спалити — найшвидше, але шрами назавжди й без ресурсів зараження.
2. **Що втрачається при провалі.** Першим закривається вимір, чий портал або регіон гравець охороняв найгірше. В останній момент гравець сам обирає один вимір, який рятує.
3. **Край світу.** Радіус ядра повільно росте з часом, але має межу. Яйце можна ставити будь-де — таймер і так змушує вирішувати.
4. **Постійні чи тимчасові зміни:**
   - після лікування світ видимо заживає за кілька днів;
   - після «спалити» — шрами назавжди;
   - після приручення змінена зона стає новим біомом.

### «Виживання», крок S1: доба, здоров'я, голод (20.10.2026, ГОТОВО)

Команди: `/time [set <день|ніч|вечір|світанок|північ|полудень|число>|add N]`, `/heal`, `/hurt N`, `/eat N` (права 2). ### «Виживання», крок S2: предмети, видобуток, дроп, режими (20.10.2026, ГОТОВО)
Предмет ≠ блок: `ItemRegistry`/`ItemSettings` (API), кожен блок автоматично має предмет-блок (крім води/корінної породи). Видобуток як у Minecraft (`core/Mining`): час = твердість × (1.5, якщо інструмент дає дроп, інакше 5) ÷ швидкість інструмента; руки не вистачає для каменю/руд (`minTier`): камінь - кирка 1 (дерево), залізо/мідь - 2 (камінь), золото/алмаз - 3 (залізо), лімініт - 4 (алмаз). Інструменти дерево/камінь/залізо/алмаз × кирка/сокира/лопата (швидкість 2/4/6/8, міцність 60/132/251/1562). Дроп - **справжні предмети на землі** (`ItemEntity`: падають, спливають, зливаються, 5 хв, підбір у радіусі 1.5 при вільному місці, зберігаються в `items.dat`), смерть у виживанні викидає весь інвентар на місці смерті. Їжа: яблуко (+4) з листя дуба 5%. Режими: виживання за замовчуванням у нових світах, `/gamemode survival|creative` (креатив - стартовий набір, миттєве ламання без дропу, безсмертя, блоки не витрачаються; старі світи без поля = творчі); інвентар зберігається у світі. Команди `/give`, `/drop`, `/clear`, `/gamemode`. Залізні/алмазні інструменти доступні лише через `/give` до S3 (крафт, піч).
**FL Client** (його клієнт для Minecraft: Auto FPS, мінікарта, зум, fullbright): Святослав «додав би на всякий» - окремий крок після S3, переписаний нативно як «клієнт-функції» Voxelin (нормальний зум, мінікарта, fullbright, block info, індикатори); код Minecraft-мода тут не запускається.

### Броня (S7, ГОТОВО)

Чотири слоти у вікні інвентарю, ПКМ з бронею в руці надягає (заміна повертає стару в руку), shift-клік надягає/знімає, `/wear`. Захист діє на удари істот (-4% за очко); кожен удар зношує випадковий шматок на max(1, шкода/4), 0 - предмет зникає; падіння/голод/утоплення не зменшуються. Рецепти стандартної форми з `leather`/`iron_ingot`/`diamond`; коваль продає залізні шолом і черевики. Броня зберігається у світі й випадає при смерті.

### Виміри й Енд (S8a/b, ГОТОВО)
**Вимір = окремий `World`** у теці `<світ>/dimensions/end/` (власна генерація, чанки, істоти, предмети); активний у клієнті один. Перехід (`Voxelin.requestTravel` -> `doTravel`): зберегти поточний -> відкрити цільовий (`Game.openDimension`) -> `WorldInfo.copyPlayerFrom` (інвентар, броня, здоров'я/голод, режим) -> завантаження з точкою прибуття; назад - у точку входу (`returnX/Y/Z`). Блок `end_portal` (не суцільний, незламний, світить): ноги в ньому -> перехід (замок, поки не вийдеш із порталу). **Енд** (`EndGenerator`): порожнеча, острів радіусом ~46, вісім обсидіанових веж, малі острівці далі 150 блоків, платформа прибуття 7×7 з **постійним виходом** (3×3 порталу), небо стале фіолетове. **Портал у звичайному світі:** підземна **Брама Шву** (`seam_gate`: кільце з 12 рамок навколо отвору 3×3, `/locate seam_gate`); **Око Енду** (рецепт безформний: уламок лімініту + алмаз + золотий злиток) ставиться ПКМ у рамку; **12-те око відчиняє портал лише якщо той, хто його ставить, у повній алмазній/незеритовій броні** (`Inventory.fullArmor(..., 4)`), інакше око повертається в інвентар і гравець бачить причину (`core/EndPortal`). Дракон Краю - наступним кроком (S8c).

### Безмежний світ (20.10.2026)
Святослав: генерація без межі, «ні спеціальної, ні математичної». Чесно: у скінченному комп'ютері будь-яке число має розмір, тож «справжньої нескінченності» не буває - але межу відсунуто так, що її не можна досягти:
- Координати блоків X/Z - `long` (±9,2·10¹⁸), чанки й регіони теж; край у коді - `World.MAX_CHUNK` (~4,6·10¹⁸ блоків від початку, лише захист від переповнення). На швидкості 10 блоків/с до нього йти ~15 мільярдів років; це у сотні мільярдів разів далі за 30 млн у Minecraft (там межа - не дизайн, а місце, де ламаються точність і генерація).
- Позиція гравця й камери - `Pos`: чанк (`long`) + зсув усередині чанка (`double`). Фізика, приціл і малювання рахуються відносно чанка гравця/камери, тож числа завжди малі й точні (перевірено наживо на 3 млн, 10¹², 10¹⁵ і −10¹⁸ блоків: чітка картинка, координати показуються точно).
- Шум - цілочисельна ґратка + 64-бітний хеш (`gen/Noise`): без повторів (старий шум із таблицею на 256 повторював візерунок кожні ~24 тис. блоків) і однаково точний на будь-якій відстані. Тест перевіряє плавність і відсутність повторів до ±10¹⁸.
- **Висота:** світ 256 блоків (y від 0 до 255), вище/нижче ставити не можна (це єдина межа будівництва, по горизонталі її нема). Дно - корінна порода неоднорідної товщини 1-3 шари (її не можна зламати); розширення вгору/вниз - окреме питання.
- Диск росте з дослідженою площею: пишуться лише змінені чанки, решта генерується заново однаково (детерміновано за зерном).

### Текстури: розміри й пакети ресурсів (ідея Святослава, 20.10.2026)
- Типово 16×16 (працює скрізь, і на слабкому ноутбуці). Потім як **вибір**: 32×32, 64×64 або всі три; гравець обирає сам, а кнопка «Автоматично» ставить 32×32 для дискретної відеокарти (NVIDIA/AMD) і 16×16 для вбудованої (Intel/AMD Radeon Graphics) - за назвою `GL_RENDERER` (це евристика, а не точне вимірювання).
- Система пакетів ресурсів: власні PNG кладуться в теку й перекривають типові (типові текстури рисуються кодом); так само працюватимуть текстури модів.
- **Атлас текстур** (одна велика картинка або масив текстур замість файла на блок) - головний прийом для FPS; **міпмапінг** для далеких блоків. Застереження: у звичайного атласа міпмапи «підмішують» сусідні текстури по краях (просвічування) - потрібен відступ між плитками або масив текстур (`GL_TEXTURE_2D_ARRAY`); вирішимо на етапі 2.

### Відомі обмеження рушія
- Інтерфейс (меню, HUD, інвентар) поки малюється старим способом `glBegin` у сумісному контексті OpenGL; світ - шейдерами й буферами GPU. Перенесемо на буфери разом із переробкою інвентарю й крафту (етап «Виживання»).
- Мікрозависання на слабкому залізі (Intel HD 4400, 4 ядра) під час швидкого польоту по новому світу: паузи збирача сміття G1 7-31 мс (копіює щойно згенеровані чанки), завантаження мешів на GPU (~2-3 мс на секцію), конкуренція потоків з робочим столом. ZGC і Shenandoah не допомогли (виміряно). Ходьба зі звичайною швидкістю навантажує значно менше.

Розростання — клітинний автомат **лише в 64 блоках від гравця**: `seam_growth` поглинає суцільні ламкі блоки (не обсидіан, не блоки з взаємодією, не незламні); на світлі (>7) шанс 0.35, вода поруч ×0.25. ПКМ без предмета — стан. Наріст у незавантажених чанках прибирається, коли вони з'являться.

## Крила Шву (елітри) — нагорода Ритуалу (рішення Святослава, 21.10.2026)
Коли падають Ткач і Розплітач, разом із Серцем Шву випадають **Крила Шву** (`seam_wings`): надягаються в слот нагрудника (0 захисту — тому з ними Енд не відчиниш), міцність 432, зношуються 1 за секунду польоту, **не ламаються** — на останній одиниці просто перестають нести. Політ: стрибок у повітрі під час падіння розкриває крила; фізика — як у крил Minecraft (дивишся вниз — розгін, вгору — набір висоти коштом швидкості; горизонтально ~10:1). Плавне планування не дає шкоди від падіння; удар об стіну на швидкості — шкода (втрата швидкості ×10 − 3). **Ремонт** (29.10.2026): у сітці крафту крила + 1–4 клітинки з уламком лімініту, кожна повертає чверть міцності (108); загальне правило «два однакових → один» теж працює, але пара крил у гравця зазвичай одна.

## Скін і косметика (29.10.2026)
- Модель гравця від третьої особи (F5): голова, тулуб, руки, ноги, анімація кроку, голова за поглядом, присід, горизонтальний політ на крилах; крила Шву видно на спині.
- **Скін у форматі Minecraft** (PNG 64x64, старі 64x32 перетворюються) - підходить скін із лаунчера. Вбудовані: Мандрівник, Сторож Шва, Шахтар, Козак. Свої - тека `skins/`.
- **Плащі**: Шов, Україна, Дракон Краю, Зоряна ніч, Жар; свої PNG 64x32 - тека `capes/`.
- Екран «СКІН І КОСМЕТИКА» з обертовою 3D-моделлю - з головного меню й з паузи.
- **Контракт для лаунчера**: файл `player.properties` поруч із `settings.properties` (тека над `saves/`):
  `skin=builtin:<traveler|keeper|miner|kozak>` | `file:<ім'я.png у skins/>` | `launcher`; `cape=none|seam|ukraine|dragon|night|ember|file:<ім'я.png у capes/>`.
  Або аргумент `--skin <шлях.png>`: якщо `player.properties` ще нема, гра бере цей скін; у списку він - «з лаунчера». Гра перечитує файл, коли відкривається екран скіна.
- **3D-косметика** (Святослав: «не як у Minecraft з 1 пікселем відступу»): моделі Blockbench (Bedrock geometry) у `cosmetics/<назва>/` + `texture.png` + `cosmetic.properties` (title, slot head|body); кістки, повороти, UV коробкою й по гранях. Вбудована (вінок зі стрічками, корона, циліндр, кепка, роги, німб, рюкзак) - у тому ж форматі. Інструкція - `docs/COSMETICS.md`. **Слоти рук і ніг (04.11.2026):** `arms`/`legs` - одна модель на обидві кінцівки в координатах шаблона гравця, кожен кубоїд іде з правою чи лівою кінцівкою за знаком x свого центру (`Cosmetic.onSide`), тож рухається при ходьбі; вбудовані: шкіряні рукавиці, золоті наручі, чоботи мандрівника, вишиті онучі. У `player.properties` - ключі `arms`, `legs`.
  - Правила Bedrock-експорту (X дзеркалиться, повороти [-x,-y,z], up/down по гранях - з протилежного кута) збігаються з перевіреними на справжньому Blockbench 5.2.2 у `fl-cosmetics-models` (test/oracle.test.js); моделі звідти (німби, крила) відкриваються у Voxelin без змін.

## Чити, правила гри, зерно (прохання Святослава, 29.10.2026)
- **Чити** вибираються на екрані «Новий світ» → «ЩЕ...» (типово «ні»; вибір «Творчий» вмикає їх, як у Minecraft, але можна вимкнути). Без читів гравцю недоступні всі команди, крім `/help` і `/seed`; це перевіряє ядро (`CommandRegistry`), тож і моди не обійдуть. Старі світи без поля - з читами.
- **Правила гри** (`GameRules`): `keepInventory` (ні), `doDaylightCycle`, `doMobSpawning`, `naturalRegeneration`, `fallDamage`, `doMobLoot` (так). Задаються перед створенням світу; у створеному - лише `/gamerule <правило> [true|false]`, тобто тільки з читами. Спільні для всіх вимірів світу.
- Вимкнена зміна дня тримає **сонце** (зсув `dayShift`), а ігровий час іде далі - інакше правило зупиняло б відлік Зараження. `doMobLoot` не стосується босів: сюжетна здобич падає завжди, щоб гру можна було пройти.
- **Зерно**: поле на тому ж підекрані; порожнє - випадкове, число - як є, текст - його хеш (як у Minecraft). `/seed` показує зерно.

## Крафти: об'ємні блоки (рішення Святослава, 29.10.2026)
- Рецепт може вимагати **кілька предметів у клітинці** (`RecipeSettings.key(c, ingredient, count)`): так об'ємні блоки коштують як куб, а не як пласка картинка.
- **Піч** = 8 бруківки кільцем, як у Minecraft (16 спробували - Святослав передумав, «забагато»); вугілля більше не потрібне (раніше для першої печі треба було знайти вугільну руду). **Верстак** - тепер **стіл** (стільниця + 4 ніжки, форма `table`): рецепт 2×2 `[дошка×2][дошка×2] / [палиця][палиця]`; з блоків дощок уже не робиться.
- **Смолоскип** (вугілля над палицею → 4): тонкий стовпчик зі світлом 14 - перше світло на початку гри. Перша форма-не-куб у мешері (`BlockSettings.shape("torch")`).
- **Бліді дошки** з блідої колоди; **цегла**: глина в печі → цеглина, 4 цеглини → блок цегли.

## Справжні дошки (рішення Святослава, 29.10.2026)
- **Дошка** - не блок, а брусок 16×4×4 пікселі (половина півблока). **Блок дощок** (колишні «дошки») лишається окремим повним блоком; розрізняємо назвами: «Блок дубових дощок» і «Дубова дошка».
- У блоці - до **16 дощок**: сітка 4×4×4, кожна дошка займає рядок із 4 клітинок **уздовж X, уздовж Z або стоячи (Y)**; напрямки в одному блоці можна мішати, аби дошки не перетинались. Одна клітинка - одна порода (дуб, береза, ялина, бліда).
- Ставлення (ПКМ дошкою): куди влучив - туди й лягає (на верх іншої дошки, впритул збоку). На верх/низ - уздовж погляду; на бічну грань - уздовж цієї грані; **з присідом - стоячи**. Ламання - по одній дошці (та, у яку цілишся); остання - клітинка порожніє.
- Дошки **тверді**: на них стоять, а на дошку чи настил (до 1/2 блока) заходиш без стрибка.
- Крафт: блок дощок → 16 дошок, 16 дошок (2×2 по 4) → блок; дошка → 2 палиці (з блока дощок палиці напряму вже не робляться).
- Як зроблено: клітинка - блок `*_boards` (форма `boards`), що саме зайнято - 48-бітна маска в `core.Boards` (`boards.dat` у теці світу); фізика, промінь прицілу й мешер беруть коробки через `World.boxes` (там само смолоскип і стіл - `World.SHAPES`).
